The whole tour, step by step

Postgres stores every table as a file split into 8 KB pages. Every row you insert lands on one of them, and almost everything in this series happens inside a page. Here a page is shrunk to hold just 4 rows, so you can watch it fill up.

  1. This is page 0 of a table called accounts, holding three rows. The strip across the top is a map of the page, from its first byte on the left to its last byte on the right.

  2. The page starts with a small header (hdr). After it comes an array of line pointers: numbered slots 1, 2, 3, each recording where on the page a row starts. This array grows from the left.

  3. The rows themselves, which Postgres calls tuples, are packed in from the right-hand end. The gap in the middle is free space. A page is full when the two sides meet.

  4. INSERT INTO accounts VALUES (4, 'dave', 400);

    dave got line pointer 4, and his tuple was packed in next to carol's. The free space is gone: page 0 is full.

  5. INSERT INTO accounts VALUES (5, 'erin', 500);

    There was no room on page 0, so the table grew a second page. A table is simply a list of pages kept in one file on disk: block 0, block 1, and so on.

  6. SELECT * FROM accounts;

    Reading the whole table is a sequential scan: page 0, then page 1, slot by slot. It's how Postgres reads any table when no index can help.
