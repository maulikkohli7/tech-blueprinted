The whole tour, step by step

When is a snapshot taken, and how long is it kept? That's the difference between the two isolation levels most apps use.

  1. -- session B
BEGIN ISOLATION LEVEL REPEATABLE READ;

    B starts a REPEATABLE READ transaction. No snapshot yet.

  2. -- session B
SELECT * FROM accounts WHERE id = 3;

    The snapshot was taken at this first query, not at BEGIN. B will reuse it for the rest of the transaction.

  3. -- session A
UPDATE accounts SET balance = 999 WHERE id = 3;

    A runs without BEGIN, so the statement is its own transaction (101) and commits immediately.

  4. -- session B
SELECT * FROM accounts WHERE id = 3;

    Still 300. B is reusing its old snapshot, and 101 started after it was taken, so 101 doesn't count.

  5. -- session B
COMMIT;

    B's snapshot is released.

  6. -- session B
BEGIN;

    A plain BEGIN uses the default level, READ COMMITTED.

  7. -- session B
SELECT * FROM accounts WHERE id = 3;

    Now B sees 999.

  8. -- session A
UPDATE accounts SET balance = 1 WHERE id = 3;

    A commits another change while B's transaction is still open.

  9. -- session B
SELECT * FROM accounts WHERE id = 3;

    B sees 1, inside the same transaction. Under READ COMMITTED every statement takes a fresh snapshot.

  10. -- session B
COMMIT;

    In short: REPEATABLE READ keeps one snapshot for the whole transaction; READ COMMITTED takes a new one per statement.
