HOT updates

Updating a row normally means adding an entry to every index. HOT (heap-only tuple) updates skip that, as long as no indexed column changes and the new version fits on the same page.

The whole tour, step by step

Updating a row normally means adding an entry to every index. HOT (heap-only tuple) updates skip that, as long as no indexed column changes and the new version fits on the same page.

  1. -- session A
CREATE INDEX ON accounts(id);

    An index on id. balance isn't indexed, so changing it changes no index key.

  2. -- session B
BEGIN ISOLATION LEVEL REPEATABLE READ;

    B will keep an old snapshot so we can see the update from both sides.

  3. -- session B
SELECT * FROM accounts WHERE id = 1;

    B's snapshot is fixed with alice at 100.

  4. -- session A
UPDATE accounts SET balance = 150 WHERE id = 1;

    A HOT update: no indexed column changed and page 0 had room. The new version (0,4) is marked heap-only, and no index entry was written. The index still says 1 → (0,1), and (0,1) points on to (0,4).

  5. -- session A
SELECT * FROM accounts WHERE id = 1;

    The index led to (0,1), which A can't see, so Postgres followed the chain inside the page to (0,4). One index entry, two tuples, one page.

  6. -- session B
SELECT * FROM accounts WHERE id = 1;

    Same entry, same chain, but B stops at (0,1), the version its snapshot sees.

  7. -- session B
COMMIT;

    Now nobody needs the 100 version of alice.

  8. -- session A
UPDATE accounts SET balance = 160 WHERE id = 1;

    Page 0 was full, so Postgres cleaned it in passing ("pruning"). The old alice was removed, but the index still points at slot 1, so slot 1 stayed behind as a redirect to slot 4. That freed room for another HOT update, at (0,5). No VACUUM needed.

  9. -- session A
UPDATE accounts SET id = 11 WHERE id = 2;

    Changing an indexed column can't be HOT: the index must learn the new key 11. Pruning first removed slot 4 entirely (no index points at a heap-only tuple) and moved the redirect on to slot 5.

  10. -- session A
VACUUM;

    bob's old version wasn't HOT, so it needed VACUUM: remove the index entry for 2 first, then free its slot.

  11. -- session A
SELECT * FROM accounts WHERE id = 1;

    Index → slot 1 → redirect → slot 5. Three updates to alice, and still a single index entry.
